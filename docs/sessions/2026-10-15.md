# Session log - 2026-10-15

# 1.17.1: the window's words, to Apple's writing guidelines

[Decision 0030](../decisions/0030-the-windows-text-follows-apples-writing-guidelines.md).

Asked (across all of the user's projects): make the text in every window
follow Apple's writing guidelines, as had just been done for Noterator and
Miderator (their decision 0053). Text only - no change to what any idea
sounds like.

- Started from 1.17 with every suite passing (about 667,000 checks).
- **Buttons and toggles** to title style: Insert at Cursor, Insert on New
  Tracks, Export MIDI File (was "Export .mid"; its width went from 120 to
  130 for the longer label), Open Folder, Play New Ideas, Project Folder,
  REAPER Folder, Choose Folder… (one ellipsis character, since it asks for
  a folder before it acts). The folder chooser's title is "Choose a Folder
  for MIDI Files". The row label "Save .mid to" is "Save MIDI files to".
- **Values keep their stored names; only labels changed.** New `name(v)`
  functions (`labelled`, `barsLabel` in `gi_idea.lua`) give 2 Bars, 0.5 a
  Bar … 4 a Bar, One Item, Half-Time, Four on the Floor, At the End, Every
  4 Bars, Step Up, Half Step Up, Truck Driver, and (hidden settings) By the
  Book, Any Named, Singer-Songwriter, Double Plagal, On the Beat, With the
  Chords. `barsName` stays as it was: it names the inserted item and the
  .mid file, which keep plain ASCII. The summary line lower-cases the chord
  pace again ("1 a bar"), as it did.
- **"Make a" is "Kind".** It only read as English with the button after it
  ("Make a Motif"). "Kind" is a noun like the labels beside it (Bars,
  Content) and is the word the code and the README use; "Idea" would have
  repeated the step's name.
- **Row labels stay in sentence case** (Chord pace, Second voice, Key
  change), as Noterator writes its own labels; one-word labels are the
  same either way. Noterator hides the Key and Scale rows by their labels,
  so those did not change.
- **Hints**: " - " to an em dash, 'and' to “and”, apostrophes curly - by a
  script over the string literals of the settings list only (52 lines),
  then read back: 29 distinct quotes and possessives, every one right.
- **Messages**: "No track is selected. Select a track, then insert.";
  "Couldn’t write to … Choose another folder below."; "Saved “…mid”. Open
  Folder shows it."; "Couldn’t open …"; "None in 6/8 — its beats are in
  threes already". The ReaImGui-missing alert is titled "Good Idea" rather
  than "Missing dependency".
- Tests: test_ui clicks the new labels (and test_idea checks "0.5 a Bar");
  the values they set are the old ones. One check missed first time - the
  unsaved project's "isn't" now has a curly apostrophe. All suites pass.
- Not changed: chord symbols, ScaleView's root and scale names, the chord
  line's marks, the step names and their "+" / "-", part and track names
  (Melody, Chords, Bass, Second voice), the item and file names, the
  ReaPack "About" text.
- Noterator and Miderator vendor `gi_idea.lua` unchanged; they pick up the
  new labels and hints when they copy it. Their settings reach JUCE as
  `std::string`, which `juce::String` reads as UTF-8 (checked in JUCE
  8.0.15's `juce_String.cpp`), so the em dashes and curly quotes are safe
  there.
- No deep sweep: no engine logic changed, only strings and label functions.
