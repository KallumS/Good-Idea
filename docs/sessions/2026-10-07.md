Asked: play sync with REAPER ("pressing play in Reaper starts playing Good
Idea", and so "a mute or ignore play button"); "click somewhere on the midi
generation and start playing from that point"; and Export .mid "doesn't
seem to work, I can't find the exported midi" - a setting for where it
saves and a button to open that folder.

  the likeliest fault was the folder: REAPER's resource path, hidden by the
  Finder and Explorer, named only in the status line. Export now goes by
  default to a `Good Idea` folder beside the saved project, the folder is
  written under the buttons, and Open folder shows it. The old place stays
  as "REAPER folder", so earlier exports can be found.

  session and reaper.fm is blocked; ReaTeam/Doc's copy of the API page on
  GitHub (REAPER 6.09) was reachable and every new call was checked there.
  REAPER has no folder chooser of its own: js_ReaScriptAPI's where
  installed, else a box to paste a path into.
- The preview was rebuilt as a position in the idea played up to on each
  wake-up, from Audition's clock or REAPER's (`GetPlayPosition2`, the
  block a stuffed note joins, rather than `GetPlayPosition`, which is
  heard an output latency later). A jump strikes again the notes held
  across the new place. Audition's Loop now keeps exact time going round
  (it used to restart from the wake-up after the end, a fraction late
  every time); the 1.0 test that said "starts again at 0" now says "near
  0, and two beats later exactly 2.02 in".
- Chosen without asking (each said in the reply): Play with REAPER ticked
  to begin with; the idea starts on the bar the edit cursor is in; never
  while recording; a click on the roll goes to the nearest beat and, with
  REAPER playing, moves REAPER there; a new idea while playing comes in at
  the same place.
- The music is untouched: the demo printed the same ideas before and
  after for all four kinds.
